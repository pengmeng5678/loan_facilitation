# 项目七 · 销售素材推广与客户激活 AI

## 业务前提（决定了这个包为什么这么设计）

公司**没有内容自运营账号**，获客第二条腿是**业务员的社交传播**：

> 每个成单客户，业务员都会在自己账号（朋友圈 / 抖音 / 小红书）发一条素材 ——
> 在老客面前是"我又帮人办成了"的口碑，在新客面前是"新客户来源"。
> 同时，那些**还在犹豫的未成单客户**，也需要被合适的素材再拉回来一次。

所以这个包做四件事，边界很清楚：

| 能力 | 解决什么 | 代码 |
|---|---|---|
| 素材生成与渠道语感适配 | 业务员不会写 / 写得不像人话 / 三个渠道发同一套 | `generator.py`、`quality.py` |
| 成单案例脱敏包装 | 最有说服力的素材（客户证言）不敢用 | `cases.py`、`desensitize.py` |
| 未成单客户激活 | "考虑中"的客户沉在库里没人管；群发又会被拉黑 | `activation.py` |
| 合规先审后发 + 效果归因 | 说错话是监管风险；发了不知道有没有用 | `compliance.py`、`attribution.py` |

**边界**：AI 只产出素材与建议，**发布与对客沟通由业务员完成** ——
对外发送是高风险、非幂等动作，走平台 HITL 审批（`platform.send_external_message`）。

## 二、素材生成：结构模板 + 渠道语感

### 固定四步链路（缺一不可）

```
① 选结构模板（钩子 → 痛点 → 方案 → CTA）
② 按渠道适配语感（字数区间 / 标签数 / 是否口播）
③ 过合规（命中就改写；不可改写的直接拦截）
④ 打质量分（可解释：哪一项扣了多少分）
```

### 渠道语感不是"措辞不同"，是读者心态不同

| 渠道 | 读者心态 | 语感要求 | 字数 | 标签 |
|---|---|---|---|---|
| 朋友圈 | 熟人刷到，戒备低但耐心也低 | 短、平、近；不要像广告 | 40–220 | 0 |
| 抖音 | 陌生人 3 秒内决定走不走 | 强钩子、口语、有冲突感，写成口播稿 | 120–420 | 3 |
| 小红书 | 有需求的人在"找经验" | 第一人称、真实感、避坑向 | 180–600 | 5 |

**"同一套文案发三个渠道"是社交获客最常见的浪费。** 所以 `ChannelSpec` 是硬约束
（字数超限 / 标签数不符 / CTA 缺失都会被质量分扣分），不是建议。

### 合规即流程约束（而不是一张检查清单）

`MaterialGenerator.assemble()` 是产出 `MaterialDraft` 的**唯一路径**，
"先审后发"因此在结构上无法绕过：

```
草稿 → assemble() → 合规审核 → 通过：approved
                              → 命中但可改写：sanitized（改写留痕，可发布）
                              → 命中且不可改写：rejected（不入激活计划）
```

`rejected` 的素材不会被激活计划采用，且生成路由的 Agent 会**必须**发起转人工
（`critique` 会检查"有 rejected 但没转人工"= 流程不完整）。

## 三、脱敏：为什么必须做在"生成之前"

素材是要发出去的，一旦漏了客户手机号就是隐私事故。所以顺序是
**先脱敏、再生成素材**，而不是"生成完再检查"：

| 类型 | 处理 |
|---|---|
| 手机号 | `139****1111` |
| 身份证 | `3201**********1234` |
| 银行卡 | 保留后四位 |
| 微信号 | 整体打码（"加我微信 X"这种引流表述还要额外判违规） |
| 金额 | 转区间（`38 万` → `30–50 万`），避免把客户真实负债暴露出去 |
| 姓名 | `张*伟`（`mask_name()`，不依赖姓名词表，冷门姓也不会漏） |

> 踩过的坑：姓名脱敏最初依赖"百家姓词表"，遇到词表外的姓就静默不脱敏。
> 现在 `mask_name()` 只做"留首字 + 星号"，与词表解耦，且案例卡直接调用它。

## 四、合规审核：规则保召回 + LLM 保精度

```
规则引擎（6 条规则 / 可复现）  →  召回可疑文本
        ↓
LLM 精判（可选，仅真实模型启用）→  压误报 + 补规则没覆盖的新型话术
```

| 规则 | 级别 | 例子 |
|---|---|---|
| PROMISE-01 承诺性话术 | high | "保证下款""百分百""包过" |
| PROMISE-02 收益承诺 | high | "零利息""免息""绝对低息" |
| BYPASS-01 规避审查 | high | "不看征信""黑户也能""包装流水" |
| INDUCE-01 诱导性表述 | medium | "秒批""无门槛""当天必到账" |
| ADLAW-01 绝对化用语 | medium | "行业第一""销量第一""唯一" |
| PRIVACY-01 敏感信息 | high | 手机号 / 身份证 / 银行卡号（正则） |

**只有 high 级才拦住发布**（medium 改写后即可发），避免"什么都不敢发"。

> ⚠️ 踩过的坑（过宽匹配 = 静默毁文案）：`SANITIZE_MAP` 里曾经写的是裸词 `("第一", "优质")`，
> 于是"**第一**件事不是继续申贷"被改写成了"**优质**件事"。这类 bug 不报错、不告警，
> 直接把对外文案改坏 —— 现在只收"排序性宣称"（行业第一 / 销量第一 / 第一名），
> 并有专门的回归测试锁住它。

## 五、客户激活：对症 + 防骚扰

### 对症（不群发）

客户的犹豫**是有原因的**，所以按犹豫原因匹配素材主题
（`_OBJECTION_TO_THEME`，纯配置、可人工维护、可 A/B）：

| 犹豫原因关键词 | 匹配主题 |
|---|---|
| 利率 / 利息 / 贵 / 费用 / 服务费 | 费用透明 |
| 办不下来 / 通过率 / 征信 / 查询 / 逾期 / 资质 | 征信解读 |
| 考虑 / 商量 / 没时间 / 再说 | 案例见证 |
| 别家 / 对比 / 便宜 / 更低 | 服务对比 |
| 流程 / 多久 / 麻烦 / 资料 | 流程科普 |

素材挑选优先级：**同主题 > 同渠道**；渠道则**跟随素材本身**
（同渠道没有对症素材时，按素材原渠道发布并在理由里注明），
不会把小红书经验贴当成朋友圈文案发出去。

### 防骚扰（这是业务红线，不是优化项）

群发激活最容易伤客户关系，所以四道闸门：

1. **沉睡阈值**：不足 N 天（默认 7）不发 → 还在正常跟进的人不该被 AI 打扰；
2. **静默期**：距上次触达不足 N 天（默认 3）不发；
3. **触达上限**：同一客户累计触达次数达上限（默认 2）不再发 ——
   **计数来自真实触达流水**，不是客户档案里的离线快照（快照会漂移）；
4. **发送时间**：避开深夜与周末，落在工作时间。

被跳过的客户会带**原因**进入 `plan.skipped`，可审计、可解释。

## 六、归因：从"产出素材"到"产出线索"

漏斗是最朴素的 `impression → consult → lead → deal`，按渠道 × 素材聚合：

```
留资最多的渠道 / 表现最好的素材 / 素材触达→成单转化率 / 各渠道线索占比
```

设计要点：

- **没有数据就不编结论**：素材档案缺失时标 `(素材档案缺失)`，并且**不据此给加量建议**；
- **结论必须能追溯到数据**：每条结论都由某个具体聚合值直接得出；
- **口径要写在 `to_text()` 里**（转化率以留资为分母），避免"同一张报表两个口径"。

> ⚠️ 踩过的坑：`to_text()` 里把聚合字段 `lead` 写成了 `leads`，
> 于是报表显示"留资 0"，而结论里写着"抖音留资最多（93 条）"。
> 报表显示 0 但结论说最多，是最典型的口径事故 —— 字段名必须以聚合层为准。

## 七、装配到平台（五条路由）

| 路由 | 触发 | 工具（作用域） |
|---|---|---|
| `generate` | 默认 / "生成素材" | `marketing.generate_materials` |
| `case` | "案例""证言" | `marketing.pack_cases` |
| `activation` | "激活""沉睡""跟进" | `plan_activation` + `activate_customer`（+ `send_external_message`） |
| `audit` | "审核""合规""能不能发" | `marketing.audit_text` |
| `attribution` | "归因""效果""哪条素材好" | `marketing.attribute` |

### 最小权限：`message` 作用域只在需要时才开放

```python
tags = list(mapping[route_name])
if route_name == "activation" and any(k in text for k in _SEND_KEYS):
    tags.append("message")   # 只有这时候 Agent 手里才有对外发送工具
```

其余情况下 Agent **根本没有**发送工具 —— 从根上杜绝"模型自己决定发出去"。
作用域裁剪在这里是双重身份：省 token（实测按路由只注入 3–5 个工具的 schema，**省 90%–94%**）+ 安全边界。

### HITL：对外发送必须人工确认

```
业务员："激活这批沉睡客户，把素材发给他"
  → 生成激活计划（防骚扰过滤，跳过 2 位并给出原因）
  → 取出该客户的触达包
  → platform.send_external_message（risk=high, idempotent=False）→ 挂起等审批
  → 审批人看到的是【素材正文 + CTA】，不含状态标注 / 质量分等内部信息
  → 批准 → 发送 → 全程留痕
```

审批超时策略只有 `abort`（放弃）和 `escalate`（升级挂起），**永远不自动放行**。

## 八、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/marketing/channels` | 渠道语感规范（字数 / 标签 / 口播要求） |
| POST | `/marketing/materials` | 批量生成素材（含合规与质量分） |
| GET | `/marketing/materials` | 素材库列表（可按状态过滤） |
| POST | `/marketing/cases` | 成单案例脱敏包装 |

| GET | `/marketing/activation/tasks` | 激活任务列表 |
| POST | `/marketing/activation/send` | 触发发送（走编排层 → HITL 挂起） |
| POST | `/marketing/audit` | 合规审核（业务员自己写的内容也能先审） |
| GET | `/marketing/audits` | 审核记录 |
| POST | `/marketing/attribute` | 素材效果归因 |
| POST | `/marketing/touch` | 记录一次触达（归因的数据来源） |
| GET | `/marketing/stats` | 素材库 / 审核 / 触达 / 激活任务统计 |

平台上注册了 6 个工具：`marketing.generate_materials` / `pack_cases` /
`plan_activation` / `activate_customer` / `audit_text` / `attribute`。

## 九、配置项

```ini
MARKETING_DATA_DIR=.data/marketing
MARKETING_DEFAULT_CHANNEL=moments            # moments | douyin | xiaohongshu
MARKETING_DORMANT_DAYS=7                     # 超过多少天未互动视为沉睡客户
MARKETING_ACTIVATION_COOLDOWN_DAYS=3         # 同一客户两次激活的最小间隔（防骚扰）
MARKETING_MAX_ACTIVATION_PER_CUSTOMER=2      # 同一客户累计触达上限
```

数据文件（`seed_data.py` 生成，生产替换为真实数据源）：

```
.data/marketing/
├── blueprints.json          # 素材结构模板（12 条：3 个渠道各 4 条，覆盖 6 个主题）
├── dormant_customers.json   # 待激活客户（含犹豫原因与沉睡天数）
└── material_performance.json# 素材效果种子（渠道 × 主题的漏斗数据）
```

激活（沉睡阈值 / 静默期 / 触达上限 / 对症匹配 / 渠道跟随素材 / 优先级 /

归因（无数据不编结论 / 漏斗计算 / 素材档案缺失标注）、
服务门面、工具注册、Agent 路由与作用域（**未要求发送时看不到发送工具**）、
HITL（挂起 → 批准 → 完成 / 拒绝 → 不发）。
