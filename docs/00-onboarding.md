# 新人 2 天上手：学习地图

> **这份文档是唯一入口。** 你不需要决定读什么、按什么顺序读——跟着下面的时间块走就行。
> 每个时间块固定四行：**读什么 / 做什么 / 产出 / 自检**。没有产出的阅读会在四小时后忘掉 80%，所以每块都必须留下痕迹。

## 怎么用这份地图

- **Day 1 只求"能讲"**：把业务链路和数据流向讲清楚，不要求改代码。
- **Day 2 才求"能改"**：定位代码、守住红线、完成小需求。
- 顺序反过来会变成"代码看了一堆，问他业务为什么这样流答不上来"——那是新人最常见的失败模式。
- 卡住超过 20 分钟就停下来问 Mentor，不要硬磕。这份地图的目标是让你快点进入 productive 状态，不是考你。

## 开始之前：三个你会反复用到的工具

```bash
# 1) 反查：这个符号在哪个文件（最常用，比 grep 快且给出定义位置）
python scripts/onboarding_check.py --probe ALLOWED_TRANSITIONS

# 2) 校验：我答案里写的代码位置对不对（Day 2 验收用）
python scripts/onboarding_check.py --answer my_answers.txt

# 3) 全链路演示：不需要任何 API Key，打印系统核心链路
python scripts/demo.py
```

**代码地图**：[`docs/10-code-map.md`](10-code-map.md) —— "我想改 X 该去哪个文件"的 40 行反查表，配合 `--probe` 使用。

# Day 1 · 目标是"能讲"

## 时间块 1（30 分钟）跑起来

- **读什么**：`docs/02-getting-started.md` 第一、二节
- **做什么**：
  ```bash
  pip install -e .                      # 或按 02 的 venv 说明
  python scripts/seed_data.py           # 灌演示数据
  python scripts/demo.py                # 跑端到端演示
  pytest --collect-only              # 看测试规模（应该是 693 个用例；别加 -q，否则汇总行被吞）
  ```
  然后起服务、打开 `http://localhost:8000/ui/`。
- **产出**：浏览器里能看到 8 个页面，每个页面都有数据（不是空白）。
- **自检**：
  - 为什么启动命令要带 `--app-dir src`？（答不出就回看 02 的"为什么命令要带 --app-dir"）
  - 演示数据里几条线索？分别停在什么阶段？

> **这一块的目的是建立信心**：一个能跑、有数据、有测试的系统，比任何架构图都更能让你安心。
> 如果你打开页面是空白，90% 是没灌种子数据——先跑 `seed_data.py`。

## 时间块 2（90 分钟）业务全景：这系统到底在帮谁做什么

- **读什么**：`README.md` 的「八个项目分别解决了什么」+ 本文下面的《业务主线速览》
- **做什么**：打开 Web 工作台，把 8 个页面逐个点一遍。每点一页，问自己"这个页面服务的是业务链路哪一环"。
- **产出**：**在纸上画出完整业务链路**（见下方模板），能说出 8 个项目各自对应链路的哪一环。
- **自检**（三题，答不上回去重读对应小节）：
  1. 公司靠什么赚钱？佣金在哪个环节收？
  2. 线索的 11 个阶段是什么？为什么要切成 11 段而不是 5 段？
  3. 「项目二」（产品知识助手）和「项目八」（流程数字员工）是什么关系？

### 业务主线速览

```
投流获客                业务员触达                资质与征信          方案与到店            成交
─────────    ─────────────────────    ─────────────────    ─────────────────    ──────────
抖音/信息流   →   电话/微信/AI 客服   →   初审 + 征信初判   →   定制方案 + 约到店   →   签约放款收佣
（留资成线索）      （项目一/三辅助）        （项目二辅助）        （项目二/八）          （HITL 审批）
```

落到系统里就是 **11 阶段状态机**（`src/flow_ops/domain.py::LeadStage`）：

```
new → assigned → first_called → wechat_added → nurturing → invited
     → arrived → proposal_ready → fee_estimated → signed
                                    ↘ lost（任一阶段都可流失）
```

**为什么要懂这条主线**：后面你读的每一行代码，都是这条链上的某一环。11 阶段是本项目最好的教学骨架——每个阶段都有对应的演示数据、对应的代码模块、对应的前端页面。

## 时间块 3（30 分钟）口述验收

- **做什么**：向 Mentor 或对着空口，**5 分钟**讲完：一条线索从录入到签约，系统在每一步做了什么、哪个项目参与了、数据存在哪。
- **产出**：能讲完，且能回答"为什么要这个阶段"而不只是"有这个阶段"。
- **过关标准**：不看文档能讲完；看了文档能补充细节。

# Day 1 · 下午：目标是"能追"

## 时间块 4（2 小时）追一条线索的完整数据流

- **读什么**：`docs/01-architecture.md` 第二节「一次请求的完整生命周期」+ [`docs/11-data-flow.md`](11-data-flow.md) 第一节 + 本文下方《四条数据流主线》速查
- **做什么**：拿种子里一条真实线索（比如走到 `invited` 的那条），从数据库开始，**倒着往前追**：
  1. 看它的 `audit_log` 有几条记录，每条记录对应哪次操作；
  2. 每条记录去代码里找到发起位置（用 `--probe` 或 10-code-map 的表 A）；
  3. 在纸上标出：请求 → 哪个 Service → 哪个 Store → 哪张表。
- **产出**：一张"这条线索的完整足迹图"，每步带文件名。
- **自检**：
  1. 一次"推进阶段"的请求，先后经过哪些类？（提示：`api.py` → `service.py` → `workflow.py` → `store.py`）
  2. 审计的四个结果态是什么？哪种是"成功拦截"而不是失败？

### 四条数据流主线（速查）

| 主线 | 覆盖项目 | 一句话 |
|---|---|---|
| AI 对话流 | 一/二/三 | 客户消息 → 网关路由缓存 → Agent 工具调用 → 内容安全 → 落库 |
| 业务流程流 | 八 | 录入 → 11 阶段状态机 → SOP 扫描 → HITL 审批 → CRM/通知 → 审计 |
| 数据中台流 | 四 | 原始对话 → 分类 → 脱敏 → **人工审核闸门** → 导出/知识 |
| 素材激活流 | 七 | 模板 → 合规先审后发 → 脱敏 → 渠道语感 → 防骚扰 → 归因 |

**最重要的两条**是业务流程流和数据中台流：前者是全系统的心脏，后者解释了"AI 用的数据从哪来、脏数据怎么被挡住"。

## 时间块 5（1.5 小时）Web 工作台 ↔ 接口 ↔ 阶段 对照

- **读什么**：`docs/08-web.md` 第一节「页面清单」
- **做什么**：打开浏览器开发者工具的 Network 面板，逐个页面操作，看每个按钮打的是哪个端点。把"页面 → 端点 → 涉及的阶段/模块"列成一张表。
- **产出**：这张对照表（至少覆盖：今日工作台、我的客户、审批中心、跟进预警、客户查进度）。
- **自检**：
  1. 「跟进预警」页面的两条数据是哪个模块扫出来的？多久扫一次？本地默认开着吗？
  2. 「客户查进度」为什么要客户 ID + 手机号后 4 位两样东西？

## 时间块 6（30 分钟）Day 1 自检

12 题，**答对 10 题以上进 Day 2**。答案都能在前面读过的内容里找到；写不出来的回去重读对应小节，不要猜。

1. 线索从 `invited` 能不能直接跳到 `signed`？在哪段代码被拦？
2. `stage_entered_at` 和 `created_at` 有什么区别？SOP 判据用哪个？
3. 首呼 SLA 默认多少分钟？在哪个配置项改？
4. 为什么房产抵押贷的额度**不能**乘月收入？相关常量叫什么？
5. 页面上显示 `rep_01`，想让新人看到"张晓东"，该改哪个文件？
6. 审计四态是哪四个？`idempotent_hit` 算成功还是失败？
7. 幂等键为什么不能是随机 UUID？正确的生成函数在哪？
8. 「到店前一页纸」由哪个类生成？它从项目二拿什么？
9. 网关的缓存有哪两种？命中判据一样吗？
10. `gateway` 包里为什么不能出现"线索"这个词？
11. 数据中台的"审核"为什么必须人点，不能批量通过？
12. 前端页面里能不能写"如果阶段是 invited 就显示倒计时"这种判断？为什么？

# Day 2 · 目标是"能改"

## 时间块 7（1.5 小时）源码地图 + 定位练习

- **读什么**：[`docs/10-code-map.md`](10-code-map.md) 全文，重点表 A 和表 B 的"不许改什么"
- **做什么**：做 **3 次定位练习**，每次用 `--probe` 或表 A 找到位置，然后打开文件确认：
  1. "我想把加微信的 SLA 从 2 小时改成 4 小时" → 找到配置项 + SOP 规则 + 前端展示三处；
  2. "我想给高风险动作加一种 `sign`" → 找到清单来源 + 描述表 + 前端翻译三处；
  3. "我想改服务费分档" → 找到试算类 + 测试 + 文档口径三处。
- **产出**：三张"改动影响面"清单（改一处要连带改哪些地方）。
- **过关标准**：每次定位 **5 分钟内**完成。

## 时间块 8（1.5 小时）七条设计原则与五个反例

- **读什么**：`README.md` 第三节「七条贯穿全局的设计原则」+ `docs/10-code-map.md` 第四节「五个看似合理的错误改法」
- **做什么**：把每条原则和代码坐标对上（10-code-map 表 C）。**重点理解反例**——新人第一周犯的错几乎都在那五个里。
- **产出**：能向别人讲清 3 个反例"为什么错、正确位置在哪"。
- **自检**：
  1. 为什么"先标已执行、再调 CRM"是错的？正确顺序是什么？
  2. Redis 锁连不上时，系统应该降级用 SQLite 吗？为什么？
  3. 素材消息能不能在 `compliance.py` 之外的地方直接发出去？为什么？

## 时间块 9（3 小时）递进练习

**完整题库（20 题，答案在折叠块里）与验收标准见 [`docs/12-self-check.md`](12-self-check.md)**。
在正式做题之前，先按下面四个热身：

| # | 练习 | 验证方式 |
|---|---|---|
| 1 | 给状态机加一条流转规则（如允许 `nurturing → invited` 的重复邀约） | `pytest tests/test_flow_ops.py -k transition` 全绿，且你补了新用例 |
| 2 | 调整一个 SOP 阈值，重灌种子，观察预警条数变化 | 预警数量符合预期，且 165/25 分钟两条仍在 |
| 3 | 给某个包加一个只读工具并注册 | `/ready` 返回的工具数 +1 |
| 4 | 加一个只读 API 端点，前端页面调用它 | `tsc --noEmit` 0 错 + 页面显示正确 |

**练习 1 是最重要的**：它会逼你同时碰领域层、状态机校验、测试三处，是理解"改动影响面"最快的方式。

## 时间块 10（30 分钟）Day 2 验收

按 `docs/12-self-check.md` 的验收单逐项过。五项全过 = 2 天目标达成：

1. **能讲**：不看文档，5 分钟口述一条线索从录入到成交，说清每步经过哪个包
2. **能定位**：随机 5 个"我要改 X"，每个 5 分钟内找到文件和函数
3. **懂边界**：说清 3 个反例为何错
4. **能改对**：完成一个不破坏现有测试的小改动（693 个用例仍全绿）
5. **会验证**：能用 `--probe` 自查代码位置，能自己跑测试验证改动

## 附：这份地图的维护纪律

- 时间块划分是按"每天 6.5 小时有效时间"排的，新人实际卡住的地方可能不同——**每次有新人走完，据实调整一次**。

- 文档里所有代码位置都用 `文件::符号` 格式，可被 `scripts/onboarding_check.py` 校验。**发现锚点失效，改文档，不要绕过。**
